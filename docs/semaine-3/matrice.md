## 4. Limites et cases vides

- **Senseur inférentiel : un seul, faible.** SI1 n'est pas configuré : c'est Copilot qui relit son propre travail, sans test exécuté. Si tu juges que ce n'est pas une vraie revue, laisse la case vide. Pour la remplir proprement, demande à Copilot de relire le diff pendant la séance et garde la conversation exportée.
- **Absents, vérifié dans les archives :** `AGENTS.md`, `.github/workflows/` (pas de CI), `.github/instructions/`, `.github/prompts/`. `.vscode/mcp.json` est cité dans `conversation-1.md` (l.179) mais n'est pas versionné et n'est pas dans les archives.
- **Pas des senseurs automatiques :** `backend/http/*.http` (requêtes lancées à la main avec REST Client).
- **Exécution en séance :** les conversations montrent un seul `typecheck` (résultat contradictoire, S2) et un lancement de test bloqué par la sandbox (S3). `lint`, `build` et `check` n'y apparaissent jamais.

## 5. Observations

1. **`npm run check` s'arrête au lint.** Lancé tel quel, il sort avec le code 1 et Vitest ne démarre jamais : le test périmé de S3 reste invisible tant que S1 échoue.
2. **S3 code en dur la liste des migrations.** Chaque nouvelle migration recasse ce test : le correctif durable est de ne plus figer cette liste. Dans les deux cas, corriger le test et non le code.
3. **Les guides sont en retard sur le code** (G3) alors que G1 et G5 exigent de garder `API.md` à jour.
4. **G1 a été écrit par Copilot** : il documente le code existant plus qu'il ne contraint. Les 3 règles contrôlées sont respectées.
5. **Dawid avait raison sur EF-32** : le refus d'une offre non publiée existe dans le code mais dans aucun test (S3).
